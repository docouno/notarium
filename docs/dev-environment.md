# Dev Environment

This is the portable development-environment contract for this repository.

## Commands

- `make deps` installs npm dependencies for the current checkout when `node_modules` is missing or stale. **No-vector by default**: it installs every workspace except the deps-only carrier `@notarium/engine-vector`, so the ~660 MB native vector stack (`onnxruntime-*`, `@huggingface/transformers`, `sqlite-vec` — about 60 % of `node_modules`) is never downloaded. A no-vector checkout degrades to FTS at runtime; the dev overlay defaults `VECTOR_SEARCH=off` to match.
- `make deps-vector` installs the same dependencies **including** the vector stack (a plain `npm ci` over all workspaces) — use it for vector/hybrid-search, embedding, chunking, or vector-index work. Pair it with `VECTOR_SEARCH=on` in `.env`.
- Switching a checkout **back** to no-vector (to reclaim the ~660 MB after a `make deps-vector`) needs `rm -rf node_modules && make deps`: plain `make deps` is idempotent (it no-ops when the workspace links already resolve) and so will **not** prune an already-installed vector stack. A fresh worktree gets the lean no-vector profile automatically.
- `make doctor` validates the environment before a dev server or test stand uses it: host workspace links, Docker Compose config, dev-image build, `ps` availability in the container, writable Vite config directory, and root-level workspace dependency resolution.
- `make dev` runs `make deps`, prepares bind volumes, builds the dev image, and starts the HMR stack.
- `make down` stops and removes the current checkout's stack.
- `make test-coverage` builds the unprivileged Docker `test` stage on top of `builder` and runs the full Vitest coverage suite there. That full-dependency, glibc environment includes `sqlite-vec`, so the native vector tests participate in the engine ratchet even when the host checkout uses the default no-vector dependency profile; the `node` user keeps permission guards meaningful; and building the parent stage also proves the production build without mutating the dev stand's bind-mounted `node_modules`. The heavyweight runner image is worktree-scoped and removed on exit; the equally isolated backup-smoke image used by `checkup` is removed after that layer too, so the complete gate does not accumulate multi-gigabyte images.
- `make checkup` is the complete portable code gate, ordered fast-to-expensive: formatting + canon links + lint + typecheck; the containerized production build and full Vitest suite with coverage thresholds; live Postgres contracts/migrations; the isolated backup/restore smoke; then e2e in the Playwright container pinned to the package version. PostgreSQL and browser targets copy a clean source snapshot from a read-only bind into invocation-scoped Docker volumes, exclude host dependencies/state, and install their Linux dependencies inside those volumes. Visual snapshots are deliberately external/gitignored; when `test/visual/visual.spec.ts-snapshots/*.png` has been synced into the checkout, the snapshot includes them and `checkup` compares the visual suite too, otherwise it reports an explicit skip and never blesses the current rendering as its own baseline — how the canonical set is fetched, compared and accepted is in [ci.md](ci.md). Its coverage, Postgres, backup, and browser processes are isolated test infrastructure and do not reuse or restart the dev stand.
- `make test-pg` starts an isolated ephemeral Postgres and runs the shared meta-DB behavioral contracts plus migration regressions from `node:24-slim` on the private database network. The no-vector dependency install and source snapshot live only in a disposable Docker workspace volume. It uses a checkout+invocation-specific Compose project, exposes no database port on the host, and removes both database and workspace volumes on exit. Direct `npm run test:pg` is the CI/expert entrypoint when `TEST_PG_URL` already points at a disposable database; without that env the live suites skip under ordinary `npm test`.
- `npm run meta-migrations:check` validates the ordered SQLite/PostgreSQL SQL pairs and their tracked checksums without opening a database. `npm run meta-migrations:checksum -- 0001_name` prints the checksum for a newly added pair but never rewrites the manifest. The migration policy and ledger protocol are canonical in [meta-db.md](meta-db.md).
- `make test-browser` copies a clean source snapshot from a read-only checkout bind into a disposable workspace volume, installs the no-vector profile there with the pinned Playwright container, and runs e2e with reports under `/tmp`. This keeps browser binaries, native Node dependencies, fonts, source, and generated output reproducible on any Docker host without consuming host dependencies or writing into the checkout.
- `make seed CASE=<name>` (re)fills the stand from a declarative catalog case — `make seed-list` to list them, `make seed-coverage` for the coverage matrix. It stops the stack, wipes the volumes, seeds the real engine **in-process with a backdated journal** (so the heatmap/feed/trash look real, not one "today" spike), and restarts. **Default login on the seeded stand: `admin` / `admin`** (override `SEED_USER`/`SEED_PASSWORD`; printed as a banner at the end). See [seeds.md](seeds.md).

## Invariants

- Each checkout owns its own root `node_modules`; the dev container bind-mounts it as `/app/node_modules`. Because the dev container reuses the host `node_modules`, the host install profile (`make deps` vs `make deps-vector`) decides whether the dev stand has the vector stack.
- The vector stack is an **optional install unit**, not a runtime fork. `@notarium/engine-vector` is a deps-only carrier workspace (no code, like `@notarium/desktop`); the engine loads `@huggingface/transformers` and `sqlite-vec` through a dynamic `import`/`createRequire`, so excluding that one workspace at install time (the default `make deps`) skips the whole subtree without touching any platform-native binaries the toolchain needs. The Docker image ships the full install so `-e VECTOR_SEARCH=on` works without a rebuild.
- Skips in `npm test` are **environment gates, not disabled tests**, and the run says which: a suite whose gate is closed is skipped under a name carrying a `[gate: …]` marker, and `test/skipSummary.ts` folds those into one line — `⇢ N skipped: … vector (make deps-vector), … postgres (make test-pg)`. The reason is declared next to each gate (`vectorGate.fixture.ts` for vec0, `postgresHarness.ts` for the live database, `test/release/fullDepsGate.ts` for the license corpus case that reads installed native packages), so a gate added later is summarized for free. An `unlabelled` group in that line is the signal to look at: it means a test was disabled rather than gated. `make checkup` opens every gate.
- `npm test` needs **`make` on PATH**: `test/backup/makefile.test.ts` drives the real `make backup` / `make restore` targets to pin the archive-publication durability contract (partial retention, hard-link commit, rollback), with `docker` stubbed. Any container running the suite therefore needs a toolchain image (`node:24`, not `node:24-slim`) — in slim the suite fails with an ENOENT on an archive that was never produced, which reads as a product bug rather than a missing binary.
- The dev image uses the Dockerfile `builder` stage and includes `procps`, because `concurrently -k` shells out to `ps` while shutting down child processes after a failure.
- `packages/web` is bind-mounted as a whole writable directory. Vite writes temporary bundled config files beside `vite.config.js` (`vite.config.js.timestamp-*.mjs`), so file-mounting only `vite.config.js` is not safe.
- Vite cache lives outside `packages/web/node_modules` via `VITE_CACHE_DIR=/tmp/.vite/web`; `/app/packages/web/node_modules` is hidden behind an anonymous volume so package-local host dependencies cannot shadow the checkout root dependencies.
- Dev build identity falls back to `null`/empty commit when git metadata is not available in the container; missing git must not produce noisy shell errors.

## Troubleshooting

If an existing checkout carries an older dev overlay, it may restart-loop with `EACCES: permission denied, open '/app/packages/web/vite.config.js.timestamp-*.mjs'`.

Update that branch to a base that contains the current dev-environment contract, then run:

```sh
make doctor
make dev
curl -sS http://localhost:$PORT/api/health
```
