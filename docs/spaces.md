# Spaces — model, isolation, deployment

Canon on spaces (#16). Decisions were fixed on 2026-06-12 (discussion in #16); here is how it works and how to use it. **Multi-tenant hardening** (a second enforced line of defense beneath `can()` for cloud with open registration — RLS, FS-boundary, compute isolation; #74 removed process-per-space) is specified by the multi-tenant security spike #76.

## Model

- **Space** — an isolated knowledge base (personal/work/archives): its own index, graph, search, tree. A space carries two roles — organization and a security boundary (#10); cross-space operations are permitted only within one principal's set of spaces.
- **A space's identity is the stable opaque `space_id`** (#100 Phase 4): the `space` column in the identity registry, the journal, membership (#10), PAT-narrowing, personal-pointer and bookmarks reference this id, while MCP delta positions use the stable project ids derived inside it — none depend on the slug. **The slug is a renameable display/URL handle** (`[a-z0-9_-]`, the contractual `SpaceSlug`; `_` allowed since #123 — it appears in the note-id, which serves as the fallback handle): a URL segment, resolved to `space_id` at the request boundary (authz preHandler); a rename retires the old slug into the `aliases` history — the old `/s/<old-slug>` redirects to the current one, nothing on the id key migrates. `displayName` is the human-readable name. The space registry is the meta-DB table `spaces`: `{id, slug UNIQUE, notes_dir, display_name, aliases, created_at}`. **`notes_dir`** is the physical folder name under the notes root (`<DATA_DIR>/spaces` by default), immutable: rename does NOT touch the FS or the engine (the folder stays under its name-at-creation; the slug drifts freely). The truth of identity travels in the root `.notariummeta` (the `space` facet, Fork A) for re-clone resilience; the registry is a derived cache + the arbiter of slug uniqueness. A host without a meta-DB (`space_id ≡ slug`: no registry for an opaque id, no rename surface) is a **programmatic** configuration: `createServer` without `metaDbUrl`. It can no longer be obtained from the env: since #101 the meta-DB path is derived from `DATA_DIR`, and an empty `META_DB_URL=` is read as "not set" (otherwise `FOO=` in compose would silently null out the path), so none-mode from the environment always arrives with a sqlite registry. Previously this worked via `META_DB_URL=''` — an undocumented emergent side effect, not a contract. The e2e fake is a special case: it injects a minimal in-memory registry in order to deliberately keep `space_id ≠ slug` and verify the id↔slug projection on the wire (#127), even though its engines are in-memory.
- **Renaming a space (#100 Phase 4, web-UI + cross-tab #123)** — `PATCH /api/s/:space {slug?, displayName?}`, an owner-need action (`space:manage`; admin gets a recovery-override, like members:manage). O(1): one registry row (slug + old→aliases) + marker heal; the seven id-keyed child tables are not touched, nor are the engine/FS. Config-pinned spaces (slug from env, re-asserted at boot) cannot be renamed (400). A slug collision → 409 (an explicit rename is not suffixed). **Address resolution is fail-closed:** every current slug beats retired history; a retired alias shared by multiple spaces resolves nowhere until the histories are disambiguated. Raw history remains in the registry/marker, while `/api/spaces` and `me.spaces` expose only aliases that still resolve uniquely, so a filtered client cannot canonicalize an ambiguous handle to the wrong accessible space. The personal space is renameable by its owner (`personal_space` holds the id → the pointer is stable), but in the UI this is deliberately not offered (its displayName is hardcoded "Personal", the slug is an internal detail). **Web**: the `Management → General` tab (`packages/web/.../GeneralTab.tsx`) — the **default** Management tab (`DEFAULT_WORKSPACE_SETTINGS_TAB='general'`; a non-manager/personal space is bounced by GeneralTab's self-guard to a tab visible to it), shown only to a manager (`canManageSpace` = owner/admin) and only where a registry exists (`capabilities.spaceCreate`). The slug+displayName fields sit **side by side** (adaptive flex-wrap). `SpaceProvider.renameSpace` calls PATCH, synchronously flips the active slug and updates the list — URL canonicalization leads `/s/<old>/…` to the new slug, preserving the current tab. **The slug field's UX (explicit editing in General) is latin-only, without transliteration** (transliteration on direct editing produced garbage: «больше»→`bol-she`): input is filtered to `[a-z0-9_-]` on the fly (uppercase→lowercase, everything else — space/Cyrillic/punctuation — is dropped), a dropped character is softly highlighted with a hint in `--warning` amber (NOT a red error). **Creating a space takes a NAME, the SERVER derives the slug** (#123): the "New space" dialog asks for a human-readable name in ANY language (previously the user typed a slug and hit "bad space slug"); the client sends only `displayName`, the server derives the handle. Derivation = the shared core `@notarium/core/slug` — specifically **`asciiSlug`**, the HANDLE half of it (#296): a handle is a URL segment under `SpaceSlugSchema`, so it romanizes latin (incl. accents via NFKD), full Cyrillic (Russian/Ukrainian/Belarusian/Serbian/Macedonian) and Greek, and the non-romanizable (CJK/Arabic/Hebrew/Thai/emoji) yields `''` → fallback to an **id-like handle** (`idToSlug(freshNoteId())`, unique). NOTE names take the other half (`slugify`), which keeps those scripts' own letters — the two axes are deliberately separate functions ([note-model.md](note-model.md#name-alphabet)); a collision of the derived handle is **softly suffixed** (`uniqueSlug`: `team`, `team-2`…, respecting occupied current+alias) — NOT a 409 (that rule is only for an explicit rename). The edge case "an id-handle collided with someone else's custom slug" is closed by the same `uniqueSlug` + a retry on the mint race. The slug is then edited in General. Slug algebra is NO LONGER aligned to the legacy engine (removed — #131). **Cross-tab (#123)**: the server sends a named SSE event `rename` (broadcast to all live viewers of the space by id, twin to `members`); the client (`SyncProvider.onRename`) does `reloadSpaces` (new slug + `reloadSpaces` re-canonicalizes the active slug via alias for space-free surfaces) + `refresh` (updates `me.spaces`). A viewer in ANOTHER space will pick up the new slug on the next switch/reload (the broadcast hits viewers of the renamed space — a deliberate caveat). **A latent bug (#100 point 2), removed structurally (#123)**: the access classifier (`libs/access`) was keyed strictly by slug → on a rename of the active space the client's `active` at render lagged behind `me.spaces` → a false `space-lost` takeover + flickering read-only chrome. Fix: `me.spaces[]` carries uniquely resolvable `aliases` (a contract), `hasAccess`/`canWriteSpace`/`canManageSpace` check slug OR aliases — a stale-but-aliased active slug resolves to the held grant.
- **Isolation at the engine-instance level (#69)**: a space = the index namespace of a Notarium engine (its own notesDir + its own index file) — isolation by construction, the engine simply has no cross-space tools. **Creating spaces from the UI is implemented (#69)**: a host with a notes root declares `capabilities.spaceCreate: true` and shows "New space…" in the switcher; a new space = `mkdir <spacesRoot>/<slug>` + a registry row, and survives a restart (recovery from the meta-DB, see "Deployment"). A zero-config host (the image default) always has a root — `<DATA_DIR>/spaces` ([single data root](architecture.md#data-root)) — so the capability is on out of the box. It honestly becomes `false` where the operator declared an **explicit topology** (`SPACES_CONFIG` or legacy `ENGINE`+`NOTES_DIR`) and did NOT set `SPACES_ROOT`: they asked for a static host, and the default root does not leak into that branch (#101) — otherwise such a host would silently also get creation and purge (`rm -rf`) over a root it never named.

## Wire — two route families

- `/api/s/<slug>/notes|tree|tree/children|notes/buckets|graph|search|status|events` — space-scoped resources. A route without a space does not exist — fail-closed by construction. `status` and `events` are per-space: the read-model (and its SSE bus) lives on the space.
- `/api/s/<slug>/notes` (POST) — creating a note (a new note has no id yet); `/api/s/<slug>/move-folder` — moving a folder (a folder has no identity outside the space's tree); `/api/s/<slug>/note?ref=` — a wikilink resolver by storage key, strictly within the space.
- `/api/note*` (GET/POST/DELETE), `/api/previews`, `/api/move`, `/api/note/revisions|revision|restore` — global id-addressable operations: **the space arbiter is the identity registry**, never a request parameter. The `GET /api/note` response carries `space` — the client uses it to scope the chrome when entering via the space-free `/n/<id>`.
- `/api/spaces` (GET list, POST create behind a capability), `/api/config` (only `capabilities` — there is no host-global default space, #99), `/api/health` — host level.
- Authz: every `/api/*` route must declare `config.authz` — a route without a declaration crashes the process at startup (`installAuthz`, an onRoute check). The explicit opt-out is `/api/health` and the anonymous auth flow (#10). The unified `can(principal, action, resource)` is populated with membership in #10 (canon — [docs/auth.md](auth.md)); the #16 handlers were not changed for it. Anonymous = 401, "no access" = 404 (anti-enumeration); `/api/spaces` returns only the principal's spaces.

## Client

- URL: `/s/<slug>` (the space home), `/s/<slug>/feed|graph|files/<path>`; `/n/<id>` stays space-free; `/` (and the old `/feed`, `/graph`, `/files/*`) redirect to the active space. The active space = the URL; the last active one is remembered in `localStorage('nt-space')` — that is where `/` leads.
- `SpaceProvider` — the client half of the layer: the list of spaces, the active slug, the switcher (sidebar, hidden on a single-space host without create), `reportNoteSpace` — entering the `/n/<id>` of another space re-anchors the chrome to the note's real space (the registry's verdict).
- SSE — one `EventSource` per active space; switching spaces = close/open the channel. On a space switch `NotesProvider` resets all in-memory state (the tree, listings, the resolution cache, the sidebar's `openSet`) with guards against out-of-order responses from the previous space.

## Server

- `SpaceManager` (`packages/server/src/services/spaces/`): slug → a live `CachedStore`, lazy boot on first access + optional idle-eviction (`SPACE_IDLE_EVICT_SECONDS`, 0 = off; spaces with live SSE subscribers are not evicted). There is no host-global "default" space (#99) — the manager holds a SET of spaces (possibly empty: a fresh password host before its first user), without a blessed slug; nothing is warmed at boot (lazy). At boot: first **re-clone adopt (#126)** — `adoptDiscovered` seeds into the registry the `space_id` of folders found on disk under `SPACES_ROOT` with a root `space` facet that are not yet in the registry (the feed is `discoverDiskSpaces` from server.ts; config spaces are adopted in the provision loop via `readSpaceFacet`); then `adoptLegacyRows` (meta-DB rows with `space=''`) only if `adoptLegacyInto` is set — it is set only by the legacy single-space env path (the only pre-#16 deployment form); then a space-registry upsert. `remove()` refuses to delete the personal space (invariant #99, the `isPersonalSpace` predicate is injected from auth).
- **Cross-host `space_id` continuity (#126):** re-cloning a space folder into an EMPTY meta-DB (another host / a fresh stand) now adopts the `space_id` from the `space` facet of the root `.notariummeta`, rather than minting a fresh local one — the id travels with the folder (mirroring #51 for the note-id in frontmatter). The logic: on a mint (no row) `provisionSpaceIdentity` takes the facet's id; a divergent facet slug goes into `aliases`; an id collision (the same id on another folder) → mint a fresh one (registry-wins), and an end-of-boot heal rewrites the marker. This is a **continuity primitive**: membership (`space_members`) on an empty meta-DB is restored separately (boot-`ensureOwners` + a grant to the first owner at setup), the full sync protocol (note/folder-id reconciliation, conflicts) is #66. **Trust in `SPACES_ROOT`:** discovery is an auto-mount of a folder from disk (P1), so `SPACES_ROOT` = the operator's volume; whoever can write there can mount a space (the facet's id/slug are regex-gated, displayName is bounded; they could write the data anyway). **Re-clone privacy (→#66):** the archived flag and membership live only in the meta-DB — a re-clone of a folder without it is discovered as a LIVE orphan space, and boot-`ensureOwners` hands it to all active admins as owner; if the folder was someone's personal space, its private agent-memory becomes readable by admins. Acceptable for a primitive (the access state was not brought along with the folder), but full restoration of membership/privacy is the job of sync #66.
- The identity registry is loaded strictly by its own space (`loadAll(space)`) — identical `file_path`s in different spaces are not conflated; the global resolution of `/n/<id>` is `findById` over the shared table (without a meta-DB — a fallback by polling live stores).
- Paths (`directory`, `destinationPath`, folder paths) are normalized on our side (`libs/relPath`, rejecting `..`/absolute) BEFORE the engine; the engine's check is a second line of defense, locked down by tests.

## Deleting a space — soft-archive (#110)

Deleting a space is two-stage: a reversible **archive** (soft) and an irreversible **purge** (hard). The #79 trash is a view-over-the-journal at the note level (restore returns a note to its space); for a whole space this does not work — **there is nowhere to restore to if the space itself is gone**, so the safety lives at the space level (a marker in the registry), not the note. The relation of the models: soft-archive (space level) ⟂ the trash (per-note) — they are orthogonal, see [docs/trash.md](trash.md).

- **Archive is a drained lifecycle, not a lone timestamp.** `active → closing` first closes fresh DB and physical admission, cancels pending/running space jobs, waits bounded process-local resource leases and store settlement, and refuses to pass an accepted restore operation. A timeout leaves durable `closing`; a retry or startup recovery resumes it. A durable note-bulk parent accepted while active remains one blocker: closing refuses new parents but permits its deterministic children to drain, and startup resumes parent/children before rechecking the lifecycle. This is not fresh admission—the ordered roster and request fingerprint were frozen before closing. Only the zero-blocker cut writes `archived_at` and advances to `archived`. Closing and archived spaces are absent from `manager.list()` and `store(id)`/`subscribe(id)` fail typed not-found, while the data/journal/index and slug reservation remain intact. Restore clears the registry marker, advances `archived → active`, and explicitly reopens the retained resource authority; the store still boots lazily without reindexing.
- **Addressing**: archive is `DELETE /api/s/:space` (the space is still live, slug-addressable). Restore/purge are host-level by **stable id** (`POST /api/spaces/:id/restore`, `POST /api/spaces/restore-many`, `DELETE /api/spaces/:id`), since an archived space has no live URL (the slug family 404s for it); the arbiter is the registry, as for the per-id note routes. `GET /api/spaces/archived` returns the principal's archived spaces, filtered by `space:manage` (memberships are intact under archive — restore brings them back). Authz: `space:manage` = owner + host-admin recovery-override (like members/rename). `restore-many` (#184) is a best-effort batch for the unified trash footer: several archived spaces are restored in a single host-level round-trip, while stale/foreign ids go into `failed[]`.
- **Permanent purge** (`SpaceManager.purge` + `metaDb.purgeSpace`) — irreversible and **only over an already-archived** space (the archive is a mandatory safety stop; a live space cannot be purged → 409). It is a resumable registry-owned saga: `purge-intent` installs the permanent writer/restore fence and an immutable cleanup manifest; one metadata transaction wipes the journal/heads/proofs/operations/outbox, identity, folders/projects, context, memberships, jobs and cursors, scrubs PAT/OAuth narrowing without widening, and drops the ordinary `spaces` row; physical cleanup then removes the notes root, engine index and job/import artifacts; finally a hidden `purged` tombstone remains. A crash or filesystem failure leaves `metadata-cleaned`/`physical-cleaned` and retries idempotently before startup disk discovery, so an orphan marker is cleanup input rather than a newly adopted space. The confirm body remains the current slug (a server-side belt against a typo in the id).
- **Invariants**: the personal space (#99) is non-archivable and non-purgeable (the `isPersonalSpace` guard). A config-pinned space (slug from env, re-asserted at boot) is non-archivable (otherwise there is ambiguity with the boot re-assert) → only runtime spaces (#69) are archived. After the active space is archived, the client falls back (personal / first readable, the #99 landing).
- **Auto-purge after N days** of archival — a durable scheduled GC, a consumer of the #105 job layer (like the trash's auto-retention in #79, deliberately deferred there); `archived_at` is already written, until #105 there is only manual permanent deletion.
- **UI — a unified Trash.** Conceptually, for the user this is NOT an "archive" but the same **Trash** (#79) as for notes, one level up: "deleted a space → it's in the Trash → restore/delete permanently". There is no word "archive" in the UI (that is the mechanism's internal name). "Delete this space" is in the Danger zone in Management→General (owner-gated, at the **right edge** under Save; the #65 danger dialog, the text "moves to the Trash"; WITHOUT an export button — export is a separate adjacent tab anyway). The Trash (`TrashPage`) is fundamentally unified: for the user it is ONE entity — a "deleted item". A note and a whole space are **one `TrashRow` component** (one checkbox, one Restore, one bulk footer); per-kind there is only the leading **type icon** (`IconDoc` for a note / `IconWorkspace` for a space — so the mix reads at a glance), the clickable title (a note opens read-only, a space has no live view) and note-only memory/external chips. **The `All | Notes | Spaces` tabs are a FILTER over one list, not different screens**: the select-all toolbar and footer geometry are IDENTICAL across all tabs, but the bulk footer itself appears only after an explicit selection. `All items | Can restore | Can’t restore` is an independent recovery filter; archived spaces belong to `Can restore`. Search is shared (always visible; notes — server-side by title, spaces — client-side by name/slug). One `useVirtualizer` over `[...spaceRows, ...noteRows]` (a single row height). The meta line is identical: `path/slug · <Author-icon> who · date` (who is resolved by `describeAuthor`, privacy #13, like a note's `deletedBy`; `archivedBy` comes from the registry's `archived_by` column). Selection is shared and action-neutral: one `Set<id>` (note-id and space-id are different namespaces), while the footer reports how many selected items can be restored. `restoreSelected` partitions the recoverable subset (spaces→`restore-many`, notes→`trash/restore-many`) without requiring unavailable rows to be manually excluded; `deleteSelected` still applies to the whole explicit selection and partitions into `purgeSpace` + `trashPurge`, the confirm reads "including N whole spaces". Without a selection there is no `Empty trash`: permanent deletion of the whole current view is done via `Select all` / `Select all N` → `Delete N forever` → a danger-confirm (#183). The space list is host-level (visible from any space). After deleting the active one — a fallback home + a "moved to Trash" toast. `SpaceProvider.archivedSpaces` loads at boot + is refreshed on archive/restore/purge and the SSE `access` event (twin #111).

## Deployment (Notarium engine, #69)

- **Default (the image, zero-config)**: there is nothing to set — a single `/data` volume ([single data root](architecture.md#data-root)), spaces live in `<DATA_DIR>/spaces`. The shape depends on the auth mode (#99):
  - `AUTH_MODE=password` (managed multi-user, the docker default): the host starts **with no spaces** — no imposed `main`. The first space is the owner's personal space, minted at setup; from then on users create spaces from the UI. Previously created spaces are **restored from the registry** (meta-DB) under the `<spacesRoot>/<slug>` convention. On already-deployed instances the former `main` will still come up — as an ordinary working space (we do not migrate).
  - `AUTH_MODE=none` (a single trusted principal: desktop, dev): there is no setup flow, so the host brings up a single home space (`<spacesRoot>/main` — the slug is kept for continuity; this is the ONLY space, not an imposed extra one).
  - `make up` works without any list of spaces. Each space's index is in `<DATA_DIR>/engine` ([single data root](architecture.md#data-root)), derived (P2): deletion = reindex at boot.
- **Explicit topology** (several spaces): `SPACES_CONFIG` (inline JSON or a path to a file) — `{"spaces":[…]}` (there is no more host-global `defaultSpace`, #99; the landing is the principal's personal space, otherwise the first readable one from `/api/spaces`; array order = priority). A space: `{"slug","displayName","engine":"notarium"?,"notesDir","indexDb"?}` (`notesDir` is required, mounted **rw**; `engine` is an optional provision, its only value is `"notarium"`). A bare single-space without Docker — `ENGINE=notarium` + `NOTES_DIR` (its single space is exactly the `adoptLegacyInto`).
- **Creating spaces at runtime (#69)**: `POST /api/spaces` does `mkdir <spacesRoot>/<slug>` + a row in the `spaces` registry + an owner grant to the creator (#10). **Durability across a restart**: such a space is not in `SPACES_CONFIG`, so at boot the host loads the `spaces` registry and restores unfamiliar spaces under the `<spacesRoot>/<slug>` convention (otherwise they would vanish — the files are intact but not served). Explicit topology without `SPACES_ROOT` ⇒ no root ⇒ `spaceCreate: false`.
- Note identity survives an engine change by construction (`notarium-id` + identity registry, P7) — a provision for a future implementation of the `KnowledgeStore` port (P8).
- Gotcha: the bind directory of the `./volumes/data` volume must be owned by uid 1000 (the image runs as it) — otherwise writes fail with `Permission denied`. The boot probe (#101) catches this before `listen` and names the directory, rather than failing the first export an hour later.
- The engine is not exposed; the world's interface to the data is only our `/api/*`.
